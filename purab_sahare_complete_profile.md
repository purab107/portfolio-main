## 4. Personal Project — GramGains

**Name:** GramGains  
**Category:** Indian nutrition and calorie-tracking application  
**Status:** Personal project / development status should be updated as implementation progresses  
**Purpose:** A nutrition tracker designed around Indian food data, food-name variations, and adaptive calorie-target recommendations.

### Product concept
Users can set a goal such as weight loss, muscle gain, or maintenance, then track meals, calories, macronutrients, water, activity, and weight trends.

### Food and meal tracking
Described features include:
- Breakfast, lunch, dinner, and snack logging
- Calories, protein, carbohydrates, fat, and fiber tracking
- Water intake tracking
- Activity/exercise logging
- Saved meal combinations for quick logging
- Barcode lookup for packaged foods
- Daily summaries and historical analytics

Confirm the implementation status of each feature before claiming it as completed.

### Indian food search engine
A custom two-stage search design:
1. **Database retrieval:** PostgreSQL `ILIKE` queries fetch up to 2,000 candidate foods.
2. **Relevance ranking:** JavaScript scoring ranks the candidates.

Described search behavior:
- Handles Hindi/vernacular prefixes and aliases (example: `H. Kela` → `kela`)
- Detects brand constraints (example: “Amul butter” should favor the specified brand)
- Uses a raw → prepared/cooked → branded food hierarchy
- Supports token-level exact and prefix matching
- Penalizes overly verbose names
- Distinguishes raw and cooked food entries

Described food data sources:
- IFCT 2017
- INDB
- Open Food Facts
- User-created foods

### Adaptive calorie-target recommendation engine
Described as an eight-stage pipeline:

**Collect → Validate → Smooth → Measure → Assess Evidence → Calculate → Explain → Await Confirmation**

Design details supplied:
- Holt’s linear exponential smoothing to reduce noise in weight measurements
- 21-day weight-trend window
- Evaluation every 28 days
- Calorie adjustments in 75 / 100 / 150 kcal increments, depending on the deviation
- 14-day cooldown between adjustments
- RECOMP mode for body recomposition
- Structured reason codes explaining recommendations
- User confirmation before applying recommendations

This should be described as an **adaptive recommendation system**, not as directly measuring metabolism. Statistical smoothing and rules-based adjustments do not, by themselves, prove clinical or scientific validity. Test against missing measurements, short-term weight fluctuations, and simulated weight histories.

### Analytics and onboarding
Described features:
- Daily calorie and macro summaries against targets
- Configurable adherence heatmap (for example, 90 days)
- Adaptive engine status card
- Goal history / audit trail of calorie target changes
- Profile fields: age, gender, height, weight, activity level, and goal
- BMR/TDEE estimates using the Mifflin–St Jeor equation
- Personalized protein, carbohydrate, fat, and fiber targets

### Tech stack

- **Database:** PostgreSQL 14+, Prisma ORM
- **Other:** Multer, Cloudinary, Nodemon, Better Auth
